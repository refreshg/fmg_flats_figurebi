# vertikali_price_matrix — ფასების მატრიცა

გუნდის ექსელის „მატრიცა" Odoo-ს ცხრილად: თითო ბინის ტიპზე (კორპუსი – ხედის
კლასი – ოთახიანობა, მაგ. `1-WS-1B`) გაყიდვის **ეტაპები**, თითო ეტაპს
რაოდენობა და ფასი მ²-ზე. რაც მეტი იყიდება ერთი ტიპიდან, ფასი ადის:
პირველი N ბინა I ეტაპის ფასით, შემდეგი N — II-ით და ა.შ.

ცალკე აპლიკაცია მთავარ ეკრანზე, დამოკიდებულება `vertikali` (ბინები).
ყველაფერი ჩანაწერია — კოდი არაფერს არ იცის კონკრეტული ტიპების, ეტაპების
რაოდენობის ან ფასების შესახებ.

## როგორ მუშაობს

1. **მატრიცები → New**, სახელი.
2. ფორმაზე ღილაკი აღარ არის — სამუშაო ადგილი ცხრილია. ცხრილის **ბინებიდან
   აწყობა** ⚙ **Actions → „ცხრილის აწყობა ბინებიდან“**-შია (D-48): პოპაპი
   ეკითხება მხოლოდ **რომელი ბინები** (პროექტი, კორპუსი/ბლოკი, ხედი,
   ოთახიანობა S / 1B / 2B …, ტიპები — მხოლოდ ის, რაც არჩეულ ბინებშია
   (სია: კონფიგურაცია → ტიპები), სტატუსი) და **სვეტების რაოდენობა**
   (რამდენი ეტაპი, მაქს. 10), პლუს „პასუხისმგებელი“ და „მიზეზი“ →
   „დაგენერირება“. პროექტის ბინები ტიპებად ჯგუფდება, თითო ტიპზე ხაზი:
   „სულ“, „გაყიდული“ (sold) და „დაჯავშნილი“ (ფასიანი ჯავშანი, reserved)
   ბინებიდან, დარჩენილი ავტომატურად; ახალი ხაზი I ეტაპზე იწყება ბინების საშუალო ფასით.
   „სულ“ ბინებიდან მხოლოდ აქ ახლდება; „გაყიდული“ და „დაჯავშნილი“ კი ცოცხალია -
   ბინის გაყიდვა ან დაჯავშნა მათ მაშინვე ცვლის, მათთან ერთად ეტაპსაც და ფასსაც (D-68). პროექტის გარეშე ხაზები არჩეული ტიპებიდან იქმნება და „სულ“
   ხელით იწერება.
3. ცხრილში თითო ეტაპს ორი სვეტი აქვს — **რაოდენობა** და **ფასი მ²**,
   ტიპზე ცალ-ცალკე შესწორებადი: უჯრაზე აჭერ და წერ, პოპაპი არ სჭირდება
   (ყოველი ცვლილება ისტორიაში იწერება). **ბოლო ეტაპის რაოდენობა თვითონ
   ივსება** (სულ − წინა ეტაპები), მაგრამ თუ პირდაპირ ბოლო ეტაპში ჩაწერ
   რიცხვს, ეს ბინები **წინა ეტაპს მოაკლდება** (III-ში 11 იყო, IV-ში 6
   ჩაწერე → III 5, IV 6); სხვა ეტაპიდან მოკლება შენი ხელით კეთდება (D-52). თუ ეტაპებზე ტიპის ბინებზე მეტს გაწერ,
   **შენახვა არ გაივლის** — შეცდომა დაგისახელებს ტიპს, გაწერილ განაწილებას
   და რამდენით სცდება (D-51). „გაყიდული", „დარჩა" და „შემდეგ
   ეტაპამდე" სვეტები ჩართვა/გამორთვადია (ცხრილის მარჯვენა კუთხის ⚙),
   რომ ფასების სვეტები ეკრანზე მოხვდეს.
3a. **გადამრთველი „ცვლილება"** ცხრილის თავზე (ერთი სახელი ორივე ღილაკზე —
   დამატებაც და მოხსნაც): ჩართავ და „+ ეტაპის დამატებაზე" ცხრილის
   მარჯვნივ ერთი სვეტის წყვილი ჩნდება — **ყველა
   ტიპზე, წინა ეტაპის ფასით** (მაქს. სულ 10 ეტაპი; ორი ეტაპი = ორი
   დაჭერა, D-49).
   დამატება თავისთავად არაფერს ცვლის: ბინები თავის ეტაპზე რჩება, ახალ
   სვეტში 0, ფასი იგივეა. შემდეგ ცხრილში უსწორებ იმ ტიპებს, რომლებსაც
   ახალი ფასი უნდა — ბოლო ეტაპი თვითონ ივსება, ამიტომ III-ს თუ 6 ბინას
   მოაკლებ, ეს 6 IV ეტაპზე გადავა (D-47). „ბოლო ეტაპის მოხსნა" უკან
   აბრუნებს (ჯერ უნდა მოიხსნას იმ ეტაპზე ხელით მიბმული ტიპები).
   ისტორიაში იწერება „ეტაპების რაოდენობა — იყო → გახდა".
3b. **გაყიდული და დაჯავშნილი ცალ-ცალკე ჩანს, ეტაპზე კი ერთად ითვლება**
   (D-53): „გაყიდ. + ჯავშ.“ = ორივე, და სწორედ ეს რიცხვი წყვეტს, რომელ
   ეტაპზეა ტიპი, რამდენი „დარჩა“ და რამდენია „შემდეგ ეტაპამდე“. ფასიანი
   ჯავშნის ბინა **თავის დაჯავშნილ ფასზე რჩება** — როცა „ფასების განახლება
   ბინებზე“ გაკეთდება, ის გაყიდულ და დაჯავშნილ ბინებს ვერ შეეხება.
4. **ეტაპი** სვეტი: „ავტომატური" = გაყიდვების მიხედვით; ან ხელით I / II /
   III … — მაშინ ტიპი იმ ეტაპზეა, სანამ არ შეცვლი. **მიმდინარე ფასი** =
   მოქმედი ეტაპის ფასი (ცხრილში მუქად ჩანს, რომელი ეტაპია მოქმედი).
5. ხელახლა „მატრიცის ფორმირება“ რაოდენობებს ბინებიდან აახლებს და,
   საჭიროების შემთხვევაში, სვეტების რაოდენობას ცვლის; ეტაპების ფასებს არ
   ეხება — ისინი ტიპებზე რჩება. **ხაზს არასოდეს შლის**: თუ ფილტრში
   მხოლოდ ორ ტიპს აირჩევ, დანარჩენები ცხრილში ისევ რჩება (D-47);
   ზედმეტ ხაზს ცხრილიდან ხელით შლი.

6. **ვინ და რატომ.** პოპაპში „პასუხისმგებელი“ და „მიზეზი“ სავალდებულოა.
   ღილაკი **„ისტორია“** (და ბარათის ზედა კუთხეში მრიცხველი) ყველა
   ცვლილების სიას ხსნის: როდის, ვინ, ტიპი, რა შეიცვალა, **იყო → გახდა**,
   მიზეზი. ფორმირება ერთი ჩანაწერია (მიზეზით) პლუს თითო შეცვლილი უჯრა;
   ცხრილში ხელით შეცვლილი უჯრაც ჩაიწერება, მიზეზი შემდეგაც შეიძლება
   დაემატოს. ისტორია არ იშლება.

## მენიუ

- **მატრიცები** — მატრიცის ბარათი და ცხრილი.
- **ტიპები და ფასები** — ყველა მატრიცის ხაზები ერთ ცხრილში, ჯამებით,
  დაჯგუფება კორპუსით / ხედით / ოთახიანობით / ეტაპით.
- **კონფიგურაცია → ტიპები** — ტიპების სია (ფორმირება და იმპორტი თვითონ
  ავსებს). ხედის კლასის კოდი (WS/BS/ORD) — Estate → Configuration → Views
  → „მატრიცის კოდი"; ცარიელი = ხედის სახელი.

## ექსელის ატვირთვა (სამეტაპიანი ცხრილი)

```bash
python tools/import_matrix.py "<მატრიცა.csv>" --csv-out matrix_import.csv      # Odoo Import-ისთვის
python tools/import_matrix.py "<მატრიცა.csv>" --upload https://<host> --db <db> --key <პაროლი> --name "ფიგურები"
```

CSV UTF-8, პირველი 11 სვეტი ექსელის სათაურებით. ხელახლა გაშვება
უსაფრთხოა (ხაზები ტიპის კოდით იძებნება).

## ცოცხალი მატრიცა (D-71)

- **„არ იყიდება"** ბინა მატრიცაში საერთოდ არ ითვლება - არც „სულ"-ში, არც ეტაპზე.
- **ახალი ბინა პროექტში** (ან ბინა, რომელიც ისევ იყიდება) თავის ტიპს უერთდება
  იმ ეტაპზე, რომელზეც ტიპი ახლაა; ჩართული „ფასები ბინებზე"-თი მისი ფასი =
  ეტაპის ფასი მ² × ფართი. ბინა, რომელიც გავიდა, ბოლო ეტაპს აკლდება.
  ტიპი, რომელიც მატრიცაში არ არის, მხოლოდ ჩატში ჩნდება - ⚙ Actions ამატებს.
- **ეტაპი უკან არ ბრუნდება**: ეტაპი ითვლება ყველაზე მეტი ოდესმე გაყიდული +
  დაჯავშნილით („მაქს. გაყიდ. + ჯავშ."), ამიტომ გაუქმებული გაყიდვა ფასს არ წევს ქვევით.
- **ეტაპის ცვლილება** მატრიცის ჩატში იწერება (შენიშვნად - ელფოსტა არავის მიდის, D-72).

## ფასების ჩაწერა ბინებზე (D-69)

მატრიცის ბარათზე გადამრთველი **„ფასები ბინებზე"**. საწყისად გამორთულია;
ერთ ბინას ფასს მხოლოდ ერთი ჩართული მატრიცა უწერს (მეორეზე ჩართვა უარს ამბობს).

1. **ჩართვა ფასს არ ცვლის.** თითო ბინა (`vk_pm_price_base`) იმახსოვრებს
   თავისი ტიპის მიმდინარე ფასს მ² - ამიერიდან ცვლილება ამ წერტილიდან ითვლება.
2. **ფასი ეტაპს მიჰყვება.** როცა ტიპის მიმდინარე ფასი იცვლება (ახალი ეტაპი
   გაყიდვით ან ჯავშნით, ფასის ხელით შესწორება, ეტაპის არჩევა), თითო
   **თავისუფალ** ბინას `list_price` ეზრდება/აკლდება `(ახალი − ძველი) × vk_area_total`-ით.
   ბინის საკუთარი სხვაობა (სართული, ხედი) რჩება. CRM, შეთავაზება, Sales,
   კალკულატორი და ბროკერის პორტალი `list_price`-ს კითხულობენ.
3. **გაყიდული და ფასიანი ჯავშნის ბინა არ იცვლება** (D-53) - ჯავშნის
   პერიოდში გაყიდული ბინა ძველი ფასით იყიდება.
4. **ჯავშანი მოიხსნა** - ბინა თავისუფალია და მიმდინარე ეტაპის ფასს ეწევა.
5. ფასი იმავე ტრანზაქციაში იწერება, რომელშიც გაყიდვა/ცვლილება: ან ორივე
   ინახება, ან არც ერთი. ყოველი ცვლილება ისტორიაშია („ბინების ფასი მ² (N ბინა)").

გასათვალისწინებელი: ეტაპი და „დარჩა" ისედაც ითვლის გაყიდულს **და** ფასიან
ჯავშანს ერთად (`qty_taken`), ამიტომ ჯავშანი ფასს ისედაც სწევს ზემოთ ახალი
მყიდველისთვის — ამ წესის აზრი ისაა, რომ ძველ მყიდველს **უკან** არ შეეცვალოს.
