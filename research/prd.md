# PRD — ვერტიკალი

## ბინების ვიზუალური ამომრჩევი და გაყიდვის ინსტრუმენტი Odoo 19-ში

**ვერსია:** 2.0 · **თარიღი:** 2026-08-23 · **მოდულის ვერსია:** `19.0.2.0.0`
**წყაროები:** [competitors_1.md](competitors_1.md) · [patterns.md](patterns.md) · [../CLAUDE.md](../CLAUDE.md)

> ამ დოკუმენტის პირველი ვერსია multi-tenant SaaS-ს აღწერდა (React, tRPC,
> $249–449/თვე). ის მიმართულება გაუქმდა: აშენდა **Odoo 19 Enterprise-ის
> მოდული ერთი დეველოპერისთვის**. ეს ვერსია აღწერს რეალურ პროდუქტს — რა
> არის, როგორ მუშაობს და რა რჩება გასაკეთებელი. კონკურენტული კვლევა
> ფიჩერების წყაროდ კვლავ ძალაშია (იხ. დანართი).

## 1. რა არის პროდუქტი

**შიდა ინსტრუმენტი სეილს მენეჯერისთვის** — არა საჯარო ვიჯეტი მყიდველისთვის.

დეველოპერი ყიდის ბინებს, რომლებიც ჯერ მშენებარეა. მენეჯერს სჭირდება:
ერთ ეკრანზე დაინახოს რა არის თავისუფალი, სად მდებარეობს კორპუსზე და
სართულზე, რა ღირს — და იქიდანვე წამოიწყოს გაყიდვის ციკლი.

**პრინციპი — standard-first:** ბინები Odoo-ს სტანდარტული პროდუქტებია,
გაყიდვა სტანდარტული ჯაჭვია (opportunity → შეთავაზება → ორდერი). Custom
კოდი მხოლოდ იქ წერია, სადაც დადასტურდა რომ სტანდარტი ვერ ფარავს:
ვიზუალური ამომრჩევი, ბინის ველები, სტატუსის ავტომატიკა.

## 2. მომხმარებლები

| როლი | რას აკეთებს | უფლებები |
|---|---|---|
| **სეილს მენეჯერი** (primary) | ამომრჩევით ბინის პოვნა, ბარათი, შეთავაზება | კითხვა + ატრიბუტების quick-create |
| **ადმინი / Sales Manager ჯგუფი** | სურათების ატვირთვა, ზონების დახაზვა, კონფიგურაცია | სრული |

მყიდველი სისტემას **არ** ხედავს — მენეჯერი აჩვენებს ეკრანს ან უგზავნის
ინფორმაციას. ამიტომ Favourites, Compare, embed, საჯარო ბმულები, ბრენდინგი
და lead-ფორმები scope-გარეთაა (გადაწყვეტილება D2).

## 3. ნავიგაცია

```
პროექტის ბარათი → გენგეგმა (ბლოკები) → ფასადი (სართულის ზოლები)
      → სართულის ზედხედი (ბინის კონტურები) → ბინის ბარათი (drawer)
```

- ყოველი საფეხური თითო პროექტზე **ირთვება/ითიშება** (`vertikali.project`:
  `use_masterplan / use_facade / use_floorplan / use_grid`)
- ავტომატური „მალსახმობები" არ არის — მომხმარებელმა უნდა იცოდეს სად დგას.
  ბლოკი ავტომატურად აირჩევა მხოლოდ თუ გენგეგმა გამორთულია და ბლოკი ერთია
- Grid / Grid+ / Properties — იმავე ინვენტარის სამი წაკითხვა ცხრილებად

## 4. რა არის დანერგილი (v19.0.2.0.0)

### 4.1 ვიზუალური ამომრჩევი (OWL client action)

| ფუნქცია | აღწერა |
|---|---|
| **პროექტის ბარათები** | ყდა, აღწერა, „X free / Y", „from …", ჩაბარების ვადა |
| **გენგეგმა** | ბლოკების კონტურები რენდერზე, დინამიური `+ add`, ფერები |
| **ფასადი** | სართულის ზოლები SVG-ზე, hover-tooltip (თავისუფალი/ფასი), სართულის ნომრების სქროლვადი ზოლი მარჯვნივ, ზოლზე კლიკი → პანელში სართულის გეგმა + ბინების სია |
| **სართულის ზედხედი** | ბინების კონტურები სტატუსის ფერით, ნომრიანი პინები (გაყიდულზე 🔒), სექციების გადამრთველი, სართულის სტეპერი; მარჯვნივ სართულის ბინების სია |
| **შახმატკა (Grid)** | ფერადი ბადე 36px უჯრებით, hover-tooltip, კლიკი → ბარათი, „Plan N floor" ბმულები |
| **ბინის ბარათი** | **drawer მარჯვნიდან** — უკან გეგმა ჩანს; გალერეა (ისრები შუაში, წერტილები), **lightbox** გადიდება, კომპასი, Unit-ის ჩანართის ყველა ველი („—" ცარიელზე), ოთახების ფართები, „მდებარეობა სართულზე", Open in Odoo |
| **ფილტრები** | Layout, Status, Orientation, Condition, View, m², Max price — ჩიპებით; **⚙ კონფიგურატორი** — რომელი ჯგუფი ჩანს, ინახება ბრაუზერში |
| **ზონების რედაქტორი** | პოლიგონების დახაზვა/გადათრევა/წერტილების რედაქტირება, Number floors…, კოპირება სართულებზე ვიზარდით |
| **ლოადინგი** | ცენტრირებული სამრკალიანი სპინერი (reduced-motion → პულსი) |

### 4.2 მონაცემები

| მოდელი | დანიშნულება |
|---|---|
| `product.template` + `vk_*` | ბინა: კორპუსი, სექცია, სართული, ოთახები, ორიენტაცია, **ხედი**, ფართები, ₾/მ² (computed store), ჩაბარება, სტატუსი, ოთახების დეტალი, **მდგომარეობა** |
| `vertikali.project` | პროექტი: საფეხურები, ყდა, აღწერა, computed სტატისტიკა |
| `vertikali.block` | კოშკი გენგეგმაზე: კონტური, ფერი, სართულები, ფასადი |
| `vertikali.view` | სურათი + ტიპი (masterplan/facade/floor), სართული+სექცია |
| `vertikali.polygon` | კონტური normalized (0–1) წერტილებით; target ან unit |
| `vertikali.layout` | **განმეორებადი ბინის ტიპი** — გეგმა ერთხელ იტვირთება, 126-ჯერ არა |
| `vertikali.unit.image` | დამატებითი სურათები ბინაზე ან layout-ზე |
| `vertikali.option` | **კონფიგურირებადი მნიშვნელობები** (Condition, View) — გუნდი თვითონ ამატებს dropdown-იდან ან Configuration → Unit Attributes-იდან |
| `vertikali.copy.plan.wizard` | გეგმის + ზონების კოპირება არჩეულ სართულებზე |

### 4.3 სტატუსი (`vk_state`)

ავტომატურად ითვლება `sale.order`-იდან: დადასტურებული ორდერი → `sold`,
draft/sent შეთავაზება → `reserved`, სხვა → `available`. ტრიგერები
`sale.order.line`-ისა და `sale.order`-ის override-ებშია, რადგან
dependency chain შეუძლებელია (იხ. CLAUDE.md).
⚠️ რეალურ გაყიდვაზე ჯერ არ გატესტილა.

### 4.4 სურათები

ყველა სურათი **`/web/image` URL-ით** მიეწოდება (ქეშირებადი, სტრიმული),
base64 RPC-ში აღარ დადის. `has_image` / `vk_has_image` computed ველები
პასუხობენ „აქვს თუ არა" კითხვას სურათის ჩამოტვირთვის გარეშე. ბინის
გეგმის fallback: საკუთარი სურათი → layout-ის გეგმა → ▦.

### 4.5 გაყიდვის ჯაჭვი

სტანდარტული: `crm.lead` → რამდენიმე `sale.order` (ჯავშანი = draft/sent)
→ დადასტურება = გაყიდვა. `crm.lead.order_ids` — custom კოდი არ დასჭირვებია.
