# PRD — ვერტიკალი

## ბინების ვიზუალური ამომრჩევი და გაყიდვის ინსტრუმენტი Odoo 19-ში

**ვერსია:** 2.1 · **თარიღი:** 2026-08-24 · **მოდულის ვერსია:** `19.0.3.5.3`
**წყაროები:** [competitors_1.md](competitors_1.md) · [patterns.md](patterns.md) · [../CLAUDE.md](../CLAUDE.md)

> ამ დოკუმენტის პირველი ვერსია multi-tenant SaaS-ს აღწერდა (React, tRPC,
> $249–449/თვე). ის მიმართულება გაუქმდა: აშენდა **Odoo 19 Enterprise-ის
> მოდული ერთი დეველოპერისთვის**. ეს ვერსია აღწერს რეალურ პროდუქტს — რა
> არის, როგორ მუშაობს და რა რჩება გასაკეთებელი. კონკურენტული კვლევა
> ფიჩერების წყაროდ კვლავ ძალაშია (იხ. დანართი).

## 1. რა არის პროდუქტი

**შიდა ინსტრუმენტი სეილს მენეჯერისთვის** — არა საჯარო ვიჯეტი მყიდველისთვის.

დეველოპერი ყიდის ბინებს, რომლებიც ჯერ მშენებარეა. მენეჯერს სჭირდება:
ერთ ეკრანზე დაინახოს რა არის თავისუფალი, სად მდებარეობს კორპუსზე და
სართულზე, რა ღირს — და იქიდანვე წამოიწყოს გაყიდვის ციკლი.

**პრინციპი — standard-first:** ბინები Odoo-ს სტანდარტული პროდუქტებია,
გაყიდვა სტანდარტული ჯაჭვია (opportunity → შეთავაზება → ორდერი). Custom
კოდი მხოლოდ იქ წერია, სადაც დადასტურდა რომ სტანდარტი ვერ ფარავს:
ვიზუალური ამომრჩევი, ბინის ველები, სტატუსის ავტომატიკა.

## 2. მომხმარებლები

| როლი | რას აკეთებს | უფლებები |
|---|---|---|
| **სეილს მენეჯერი** (primary) | ამომრჩევით ბინის პოვნა, ბარათი, შეთავაზება | კითხვა + ატრიბუტების quick-create |
| **ადმინი / Sales Manager ჯგუფი** | სურათების ატვირთვა, ზონების დახაზვა, კონფიგურაცია | სრული |

მყიდველი სისტემას **არ** ხედავს — მენეჯერი აჩვენებს ეკრანს ან უგზავნის
ინფორმაციას. ამიტომ Favourites, Compare, embed, საჯარო ბმულები, ბრენდინგი
და lead-ფორმები scope-გარეთაა (გადაწყვეტილება D2).

## 3. ნავიგაცია

```
პროექტის ბარათი → გენგეგმა (ბლოკები) → ფასადი (სართულის ზოლები)
      → სართულის ზედხედი (ბინის კონტურები) → ბინის ბარათი (drawer)
```

- ყოველი საფეხური თითო პროექტზე **ირთვება/ითიშება** (`vertikali.project`:
  `use_masterplan / use_facade / use_floorplan / use_grid`)
- ავტომატური „მალსახმობები" არ არის — მომხმარებელმა უნდა იცოდეს სად დგას.
  ბლოკი ავტომატურად აირჩევა მხოლოდ თუ გენგეგმა გამორთულია და ბლოკი ერთია
- Grid / Grid+ / Properties — იმავე ინვენტარის სამი წაკითხვა ცხრილებად

### 4.3 სტატუსი (`vk_state`)

ავტომატურად ითვლება ორდერებიდან (v3.0-ის სემანტიკა): `reserved` =
დადასტურებული ორდერი (ნაშთი რეზერვშია), `sold` = ვალიდირებული მიწოდება
(`qty_delivered > 0`), სხვა → `available`. **draft/sent შეთავაზება ბინას
აღარ აკავებს.** ტრიგერები `sale.order.line`-ის, `sale.order`-ისა და
`stock.picking`-ის override-ებშია, რადგან dependency chain შეუძლებელია
(იხ. CLAUDE.md). ✅ სრული ციკლი გატესტილია ცოცხალ ბაზაზე.

### 4.4 სურათები

ყველა სურათი **`/web/image` URL-ით** მიეწოდება (ქეშირებადი, სტრიმული),
base64 RPC-ში აღარ დადის. `has_image` / `vk_has_image` computed ველები
პასუხობენ „აქვს თუ არა" კითხვას სურათის ჩამოტვირთვის გარეშე. ბინის
გეგმის fallback: საკუთარი სურათი → layout-ის გეგმა → ▦.

### 4.5 გაყიდვის ჯაჭვი (v19.0.3.0.0 — დანერგილია)

```
opportunity (+ ბინები vk_unit_ids) → Reserve → sale.order confirmed
   → ნაშთის რეზერვი → Contract Signed → Mark Sold → ნაშთის ჩამოწერა
   → (ან Cancel → ნაშთი ბრუნდება)
```

- ლიდზე ღილაკები: **Choose Units** (სელექტორი pick-რეჟიმში, ბარათზე
  „Attach" ღილაკით), **Show on Plan** (მიბმული ბინები გეგმაზე წყვეტილი
  კონტურით), **Reserve** (ქმნის და ადასტურებს ორდერს)
- **ნაშთი = ორმაგი გაყიდვის კონტროლი**: თითო ბინას 1 ცალი აქვს საწყობში;
  დადასტურება რეზერვავს, მიწოდების ვალიდაცია ჩამოწერს, გაუქმება აბრუნებს.
  დაკავებულ ბინაზე მეორე დადასტურება → შეცდომა ბინის კოდით
- `sale.order.vk_stage`: **Reservation → Contract → Sold / Cancelled**,
  statusbar ორდერზე + Estate → Reservations (kanban ეტაპებით, list ფერებით)
- draft/sent შეთავაზება ბინას **არ** აკავებს — პარალელური შეთავაზებები
  დაშვებულია; მხოლოდ რეზერვაცია ხსნის ბაზრიდან
- **გაუქმება ყოველთვის აბრუნებს ნაშთს** — გაყიდვის (done მიწოდების)
  შემდეგაც: ავტომატური return transfer (v3.2.x)
- **დაკავებული ბინის მიბმა იკრძალება** ლიდზეც და შეთავაზებაზეც —
  სერვერის guard-ები + ბარათზე ღილაკების დამალვა (v3.3)
- შეთავაზების აწყობაც ვიზუალურია: ორდერზე **Choose Units** → pick-რეჟიმი,
  Attach = ორდერის ხაზი (v3.2)
- სრული ციკლი გატესტილია API-ით ორივე მიმართულებით (გაყიდვა და გაუქმება,
  მიწოდების შემდგომი გაუქმების ჩათვლით)
